快速开始
1
配置模型路径
编辑 config.py，填写 LLM_MODEL_PATH、MEGA_ASR_REPO_DIR、MEGA_ASR_CKPT_DIR、OMNIVOICE_MODEL_PATH
2
安装依赖
pip install torch --index-url https://download.pytorch.org/whl/cu126 pip install -r requirements.txt
3
启动 LLM + ASR 服务（两个终端）
终端 1: python3 step1_setup_vllm.py 终端 2 (首次): python3 step2_asr_module.py --materialize 终端 2: vllm serve <CKPT>/mega-asr-vllm-materialized --port 8001 --gpu-memory-utilization 0.30 --dtype auto
4
运行助手
python3 step4_main.py --mode stream

⚠️ 不要安装 qwen-asr[vllm]，与 vLLM 0.19.1 冲突。vLLM 模式使用预合并 LoRA checkpoint。

实验推进历程
Round 1: 初始实现
搭建 Ministral-3-8B + Qwen3-ASR + LangChain 原型
vLLM 服务化部署 LLM，ASR transformers 后端，LangChain Agent tool calling
Round 2: 流式 ASR 模式
新增 vLLM 流式 ASR 后端
qwen-asr[vllm] 与 vLLM 0.19.1 版本冲突，无法运行
Round 3: 双 vLLM 服务架构
利用 vLLM 0.19.x 原生 Qwen3-ASR 支持
ASR 改用 HTTP Transcriptions API，无需 qwen-asr[vllm]
Round 4: OmniVoice TTS 集成
新增 step5_tts_module.py（OmniVoice 懒加载）
Agent 注册 synthesize_voice_reply 工具
System prompt 强制 LLM 每次回复走 TTS
Round 5: Mega-ASR 升级 (当前)
Qwen3-ASR-0.6B → Mega-ASR (1.7B + LoRA + 路由器)
transformers 模式启用 LoRA 动态路由
vLLM 模式预合并 LoRA 避免依赖冲突
基础模型从 0.6B → 1.7B，识别精度和鲁棒性提升
